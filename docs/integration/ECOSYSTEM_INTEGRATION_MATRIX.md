# GULA Ecosystem Integration Matrix

## الهدف

تستخدم هذه المصفوفة لتنسيق جميع المستودعات حول GULA باعتبارها **المحور السريري المركزي**. كل خدمة تحتفظ بقاعدة بياناتها ومجالها الخاص، وتتواصل مع الخدمات الأخرى عبر غلاف أحداث versioned أو حزم مزامنة موقعة عندما تكون الخدمة غير متصلة.

> لا يجوز لأي خدمة خارج GULA اعتماد نتيجة مخبرية أو تغيير حالة سريرية نهائية. يمكن للخدمات المتخصصة إنتاج بيانات أولية أو لوجستية، بينما يقوم GULA بالتحقق والمطابقة والمراجعة السريرية والاعتماد وفق RBAC والسياسات الوطنية.

## قواعد عامة

يجب أن يحتوي كل حدث على `event_id` و`event_type` و`schema_version` و`source_service` و`tenant_id` و`occurred_at` و`actor_id` و`entity_id` و`correlation_id` و`idempotency_key` و`payload`. تُرفض الحقول العلوية غير المعروفة، وتُرفض الطوابع الزمنية غير المرتبطة بمنطقة زمنية، ويجب أن يرفض المستهلك أي إصدار غير مدعوم بدلاً من التخمين.

تستخدم الخدمات المتصلة HTTP موثقاً بحساب خدمة ذي نطاق محدد. أما `identity-credential`، المصمم للعمل دون اتصال، فيستخدم حزمة تصدير واستيراد موقعة تمر عبر محول مضبوط؛ ولا يتم فتح منفذ شبكة مباشر يتجاوز سياسة التشغيل غير المتصل.

## مصفوفة المسؤوليات

| الخدمة | المجال المملوك | ما ترسله إلى GULA | ما لا تملكه |
|---|---|---|---|
| GULA Platform | السجل السريري، المطابقة، السياسات، المراجعة | أحداث القرار والسياسات والنتائج المعتمدة | لا يفوض الاعتماد السريري |
| LabLink-Core | قراءة الأجهزة والتطبيع | `device.observation.pending` | لا يعتمد النتائج ولا يكتب قاعدة GULA مباشرة |
| Receipt-and-delivery | حركة العينات وسلسلة الحيازة | `sample.custody.transitioned` | لا يعتمد نتيجة المختبر |
| INWP | القوى العاملة والتكليفات والحضور | claims حدّية موقعة وأحداث assignment | لا يرسل بيانات موظفين غير لازمة ولا يملك صلاحية سريرية |
| identity-credential | دورة حياة الهوية والبطاقة دون اتصال | حزم موقعة من claims الهوية الدنيا | لا يفتح API مباشراً ولا يقرر الأهلية السريرية |
| Front-end | العرض والتفاعل | لا يكتب قواعد البيانات المتخصصة مباشرة | لا يتجاوز API أو RBAC في GULA |
| OGLG | المراسلات الحكومية دون اتصال | روابط وثائق وأحداث مراسلات موقعة | لا يغير بيانات المرضى أو نتائج المختبر |
| govlab-platform | سطح المكتب والتشخيص والمرونة | تقارير تشغيلية مضبوطة | لا يصبح نظاماً سريرياً بديلاً |

## مسار الحدث السريري

تنتج LabLink ملاحظة جهاز بحالة `pending_review`، وتنتج Receipt-and-delivery انتقالاً موثقاً في custody. يستقبل GULA الحدثين في Inbox دائم، ويتحقق من tenant وsample وidempotency، ثم يضع البيانات في مسار المراجعة. لا يتحول الحدث إلى نتيجة معتمدة إلا بعد تحقق العينة وسياق التفويض ومرور state machine السريرية.

## مسار الهوية غير المتصل

تصدّر `identity-credential` حزمة موقعة تتضمن الحد الأدنى من claims، مثل معرف subject وإصدار الحزمة وحالة credential وتوقيع المصدر. يقوم محول GULA بالتحقق من التوقيع والإصدار وعدم التكرار قبل إنشاء حدث `identity.subject.mapped`. لا يتم استيراد صور أو قوالب أو سجل الهوية الكامل إلى GULA ما لم توجد حاجة قانونية ومصرح بها.

## معيار قبول أي مستودع جديد

لا يُعتبر المستودع متكاملاً لمجرد وجود عميل HTTP. يجب أن يملك عقداً versioned، ومفاتيح idempotency مستقرة، وسجل تدقيق محلياً، وآلية retry أو offline queue، واختبارات رفض للتعارض والحقول الزائدة، ومصفوفة صلاحيات تثبت أن GULA لا يُستبدل كنظام سريري مركزي.
